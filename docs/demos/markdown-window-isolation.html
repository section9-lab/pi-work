01 / 固定的是窗口，不是总历史

向前移动 60 条，保留 40 条重叠

原来：901 ━━━━━━━━━ 1000　（100 条）
向前：841 ━━━━━━━━━ 940　（仍为 100 条）
重叠：901 ━ 940　→ 用原消息 ID 恢复阅读位置

每页仍然可以获取 100 条。新取出的数据先进入缓存，只选择当前窗口需要的部分挂载。被移出窗口的消息没有删除，点“后一页”或“回到最新”即可重新展示。

本页“更早一页”会先模拟用户到达窗口顶部，再加载。高亮行是加载前的锚点；布局后把同一行恢复到相同位置，避免突然跳回最新回复。

02 / 不再把内容变化当成结构变化

一个回复变长，不等于列表变了

文本变化　→ 当前回复自己的观察对象
新增消息 / 切换会话 / 导航　→ WindowModel
提问导航 / 输入历史　　　　→ 独立缓存，按需失效

跟随最新回复时，仍然必须解析增量、更新该回复并处理高度变化；不会“零布局”。隔离的是不必要的父层投影和旁支计算，不是屏蔽正常的自动跟随。

阅读旧历史，且当前回复已在窗口外时：增量照常进入 Store，但这片历史阅读区没有内容变化，也就不需要因每个文本增量重新投影。完成、报错、新消息插入等结构或状态变化仍需正常通知。

交互说明与实现中需要守住的边界
  • 演示每 200 ms 展示一组增量，共 30 组，不把模拟输入频率当原生吞吐量。“单步”适合观察一次事件的通知范围。
  • 橙色边框表示父层投影被触发；绿色回复闪烁表示局部内容更新。动画仅用于解释通知边界，不代表所有行真的重新绘制。
  • 新消息插入、过滤条件变化、工具分组变化、切换会话，都可能改变窗口结构；生产实现需要明确修订号与缓存失效规则，不能只在首次打开时缓存。
  • 取消生成、离开会话和完成输出需要立即刷新或正确取消订阅。缓存历史耗尽、跨窗口选中文本、图片延迟改变高度也需要额外测试。
  • 两边共享同一条增量内容，但窗口覆盖范围可以不同；因此“阅读历史”后右侧可能已卸载当前回复，而左侧还保留它。这正是窗口策略的区别。
