# PiWork 0.1.56

## 内置 Pi 从 1.5.0 升到 1.7.0

这一版没有改任何 Swift 代码，全部改动在 `AgentHost/`：内置的 Pi Coding Agent SDK 从 1.5.0
升到 1.7.0（`pi-ai` / `pi-coding-agent` / `pi-tui` 三件套一起，`bun.lock` 重新生成），运行时的
`piWorkRuntime.version` 从 1.2.0 记为 1.3.0。设置 → 通用 / 关于里显示的 bundled agent 版本会变成
1.7.0。

跨过的是 1.5.1、1.5.2、1.6.0、1.6.1、1.7.0 五个版本。升级过程中真正需要我们改代码的只有两处：

- **MCP 工具命名函数的搬家**。1.7 把 `mcpNamespace` / `createMcpToolName` 从 `pi-coding-agent`
  的内部路径移到了 `@earendil-works/pi-mcp` 的公开 API。`AgentHost/src/mcp-native-adapter.ts`
  改成从 `pi-mcp` 导入，并把它钉在与 SDK 同一个 1.7.0。实现逐字节相同（`mcp__<server>__<tool>`、
  非标识符字符换成 `_`、64 字符上限、超长时拼 `sha256(server\0tool)` 前 8 位），所以已保存的
  MCP 只读策略、会话记录、审批提示里的工具名不会变。新增 `AgentHost/tests/mcp-naming.test.ts`
  把这个命名契约钉住，以后再搬一次会先在单元测试里炸掉。
- **扩展 widget 的渲染结果变成只读**。1.6 起 `Component.render()` 返回 `readonly string[]`。
  `AgentHost/src/acp-extension-ui.ts` 的 `setWidget` 发布函数改成接收 `readonly string[]`；行内容
  本来就要过一遍 `stripTerminalSequences` 重新生成，不存在原地改写 Pi 缓存数组的问题。

逐条核对过、确认不影响我们的破坏性改动：

- `SettingsManager.getShowCacheMissNotices()` / `setShowCacheMissNotices()`（1.6.1 换成
  `getNotices()` / `setNotice()`）、安装遥测 API 和 `PI_TELEMETRY`（1.7 移除）——全仓没有引用。
- 1.5.2 起工具参数校验走 `pi-schema`，`Type.Refine()` / `Type.BigInt()` / `Type.Undefined()` /
  `Format.Set()` 之类超出 JSON Schema 的写法不再生效——我们用 `Type.Object` 写普通 JSON Schema，
  不受影响。
- `AgentSession.dispose()` 仍是同步方法，Host 的 handle 清理逻辑不用改。

顺带有收益的修复（都来自上游，不是我改的）：MCP 服务器把请求 id 回显成字符串导致的超时、
超大会话（十几万条之后）加载时 `Maximum call stack size exceeded`、大消息/大行被二次扫描造成的卡顿、
临时性 provider 故障的重试覆盖面、Copilot 上改 thinking level 会丢 prompt cache。

验证（本地实测，不是推断）：

- Host：`bun run typecheck` 通过；`bun test` 287 个用例全过（30 个文件，856 个断言），比升级前的
  285 个多了 2 个命名契约用例。
- 用构建产物跑的同一套 Host 测试：279 过 6 失败；这 6 个用「升级前那次提交」重新构建的 bundle 跑
  也一样失败，属于既有的 bundle 模式差异，不是本次回归。
- 真进程冒烟：拿一份 1.5 运行时写下的 17.6 MB 会话文件，跑 `initialize` / `session/list` /
  `session/preview` / `session/new` / `session/close` / `session/exportHtml`，1.5 bundle 与 1.7 bundle
  的输出除 `piVersion`、`runtime.version` 外完全一致。
- 打包 / 发布工作流 / appcast / CI 依赖单元测试：51 个全过。

- 应用更新检查、工程变更检查、agent runtime 恢复检查：通过。

## 新增：本地模式（不需要账号也能用）

问题：启动页只提供 Google 与邮箱验证码两种登录，两者都要连云端认证服务。云服务一挂，未登录的人进不来，
已登录的人也会被踢出去 —— 因为登录态过期后的刷新失败会在 `AuthSession.restoreSessionOnLaunch()` 里被
当成“凭据失效”，直接删掉 Keychain。

改动分两层：

1. **账号状态从布尔变成三态**（`PiWork/Core/Auth/Manager/AuthAccessMode.swift`）。`signedIn` / `local` /
   `signedOut`，持久化在 `auth.accessMode`；旧的 `auth.isSignedIn` 会被迁移并继续写入，方便降级。
   根视图的闸门从 `isSignedIn` 换成 `canUseApp`（`PiWorkApp.swift:115`、`:159`），所以本地模式下
   agent host、会话、定时任务、computer use 都照常启动。本地模式**不写假 token**、不伪造 `AuthUser`、
   不发任何认证请求（有测试断言 0 次网络调用）。
2. **离线容错**。`AuthError` 新增 `networkUnavailable`：传输层失败、5xx、429 都算“暂时不可用”，
   这类错误**不再删除** Keychain 凭据，会话保持 `signedIn` 并以 `isOffline` 标记，后台按
   20s/45s/90s/180s/300s 退避重试。只有云端明确拒绝（4xx，例如 `invalid_grant`）或 token 无法解析时才清凭据。
   `OpenAuthClient` 的 token 请求加了 10 秒超时（原来是 `URLSession.shared` 的默认 60 秒），
   冷启动不会再卡一分钟。

界面：

- 登录页每一步下方都有“以本地模式继续”＋一行说明，错误信息显示在它上面 —— 云挂掉时这就是第一眼能看见的
  下一步。无障碍：真 `Button` + `accessibilityHint`。
- 侧边栏账号行在本地模式显示“本地模式 / 未登录”，离线时显示“离线，正在重试”；账号菜单最后一项从
  “退出登录” 换成 “登录…”，点它回到登录页。登出语义不变：回登录页，不会静默掉进本地模式。

验证：

- 新增 `PiWorkTests/AuthAccessModeTests`（5 个）与 `PiWorkTests/AuthSessionModeTests`（11 个）：
  迁移、本地模式不碰 Keychain、本地模式重启仍生效且零网络请求、有效期内的 token 零请求、
  网络不可达重试后恢复、5xx 保留凭据、401 清凭据回登录页、后台退避重试恢复会话。
- 原生 XCTest：893 个用例，0 失败，1 个跳过（本次改动前实测 877）。SwiftLint 对改动文件 0 违规。
- 已知边界：分析埋点用的是安装 ID（`AppAnalytics.swift:58`），本来就与账号无关，所以本地模式不会带上
  任何账号信息；认证之外的云端依赖不在这次范围内。

## 两个既有问题（不是本版引入）

- **打包出来的 HTML 导出找不到模板**：`pi-coding-agent` 的 `getExportTemplateDir()` 在非
  `bun build --compile` 情况下会去找 `<packageDir>/dist/core/export-html`，而
  `scripts/package-agent-runtime.py` 把资源放在 `export-html/`。所以 `session/exportHtml` 会报
  `ENOENT ... AgentHost/arm64/dist/core/export-html/template.html`。已安装的 0.1.55 用同样方式验证，
  报错完全一样，属于既有问题，单独排期修。
- **SwiftLint 基线会随文件行数漂移（本版已修）**：`.swiftlint.baseline.json` 按「文件 + 行号 + 消息文本」
  匹配，而 `file_length` 的违规就报在文件最后一行、消息里还写着「currently contains 5767 lines」，
  于是文件少一行就被当成新违规。`ChatView.swift`、`ModelProviderSettingsView.swift`、
  `SessionComposerTests.swift` 的 5 条存量违规常年卡住 `scripts/check-local.sh` 的最后一步。
  现在换成按条数记预算（见下）。

## 新增：lint 预算闸（修掉基线的漂移）

`scripts/lint.sh` 不再用 SwiftLint 自带的 `--baseline`。原因就是上面那条：SwiftLint 按
「文件 + 行号 + 消息文本」匹配，尺寸类规则（`file_length`、`type_body_length`、
`function_body_length`、`cyclomatic_complexity`）的文本里带着被测大小，文件一变大小就失配。

改成：

- `scripts/lint-budget.json`：按「规则|文件 → 条数」记录存量（当前 121 组 / 330 条，与改造前一致，
  说明没有新增违规，只是原来的 5 条不再误报）
- `scripts/lint_gate.py`：读 SwiftLint 的 JSON 报告，条数超预算或出现新的「规则 + 文件」就失败，
  并打印「预算 N，当前 M」
- `scripts/lint.sh`：`staged` / `files` 模式加 `--partial`，不会把没 lint 的文件误报成“债还清了”
- `scripts/test_lint_gate.py`：10 个单测（漂移仍放行、多一条失败、新文件失败、路径归一化、
  `--partial` 语义、预算文件本身排序与相对路径），已并入 `scripts/check-local.sh`

实测对照：给一个带存量 `file_length` 的文件尾部加一行注释，旧机制 `--baseline` 立刻报
`File Length Violation ... currently contains 3298`（exit 2），新闸放行；再塞一行 `print(`
则被拦下（exit 1，`no_print ... 预算 0，当前 1`）。

已知取舍：同一文件同一规则下「修掉一条、又加一条」会被放过 —— 键里不含行号和文本才能不漂移，
这种交换只能靠 review。`docs/lint.md` 里写清了。

`scripts/check-local.sh` 现在能一次跑到底（之前会死在 lint 那一步）。

## 顺手修的：侧边栏 Chat / Work 切换不跟内容抢主线程

切换胶囊的位移曲线从 `easeOut(0.2)` 换成轻微回弹的 spring，并把胶囊拆成独立的
`Equatable` 子视图：切 tab 时列表和详情的重建、以及会话加载完成后的 store 刷新，不再
反复重算正在动画的那一层。胶囊的形状、颜色、阴影、尺寸和位置代码一行没改。

实测（临时 `AnimatableModifier` 记录每帧时间戳，Debug 构建自动切 tab）：最大掉帧从
26.1 / 26.3ms 降到 19.5 / 19.7 / 19.8ms。`SidebarHoverActionsTests` 60 个用例全过。
