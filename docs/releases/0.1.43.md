# PiWork 0.1.43

## 对话性能

- 流式文本按 part 增量累积，只在 80 ms 发布窗口或结构事件时物化，去掉每个 token 的整串复制。
- Markdown 只解析活跃尾部并冻结完成块；完成时仍做一次最终解析，保证结果一致。
- 行离屏或窗口被遮挡时暂停流式 Markdown 解析，文本继续累积。
- 远离视口的行用实测高度占位，不再挂载完整 Markdown/工具视图；窗口缩小为 48 条源消息（28 条移动、20 条重叠）。
- 消息图片只解码为 Retina 缩略图并缓存；按需工具输出改为 16 条/2 MB 的 LRU。

### 结果与已知限制

- 1,000 条复杂历史 + 复杂流式回复：mounted p95 从 63.6 ms 降到 6.4 ms，forced p95 从 250.5 ms 降到 12.3 ms，CPU 降低约 37–40%。
- 复杂回复完成时仍可能有一次约 1 秒的布局停顿；已定位为完成行的首次完整布局，暂接受该一次性成本。

## Conversation performance

- Batches streamed text per part and materializes it at the 80 ms publish boundary or before structural events, removing whole-string copies per token.
- Parses only the active Markdown tail while freezing completed blocks; one final parse keeps the completed result canonical.
- Pauses streaming Markdown parsing while a row is offscreen or the window is occluded; text keeps accumulating.
- Far rows keep their measured height as placeholders instead of mounting full Markdown or tool views; the window is 48 sources (28-source moves, 20 overlap).
- Decodes message images once into a cached Retina thumbnail and bounds on-demand tool output to a 16-entry/2 MB LRU.

### Results and known limitation

- 1,000 complex history sources with a complex live reply: mounted p95 63.6 ms -> 6.4 ms, forced p95 250.5 ms -> 12.3 ms, and CPU down about 37-40%.
- Completing a complex reply may still pause for about one second. Profiling localized this to the first full layout of the completed row; the one-time cost is accepted for now.
