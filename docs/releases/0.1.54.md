# PiWork 0.1.54

## 修复扩展目录搜不到真实存在的包

- 搜索时不再向 pi.dev 发送 `type=extension` 过滤。pi.dev 只把“在包里声明过 pi 类型”的包算作 extension，而很多可安装的扩展没有这份元数据，会被服务端直接过滤掉。实测 `name=pi-pstack-v2`：带过滤 0 条，不带过滤 1 条。
- 解析时把“没有类型声明”当作未知而不是“不是扩展”，只有明确标成 `skill` / `prompt` / `theme` 且不含 extension 的包才丢弃。
- 浏览仍保留 pi.dev 的精选扩展列表，行为不变。

## “没有匹配”不再显示成“无法搜索 pi.dev”

- 旧逻辑把“返回 0 条”当成解析失败并抛出 `catalog_parse`，于是任何搜不到的关键词都显示成网站坏了。
- 现在按 pi.dev 自己的空状态判断：页眉计数为 `0 / N` 或页面出现 `packages-empty` 时返回空结果，正常显示“暂无匹配的扩展”；只有页面结构真的读不懂时才报解析失败。
- 浏览页返回空仍然视为失败，并保留上一份缓存目录，不会被空响应覆盖。

## 扩展目录支持翻页

- 浏览不再停在 pi.dev 返回的第一页（50 条）。页脚显示“已加载 50 / 3172 个扩展”，点“加载更多”每次追加 50 条，加载中按钮禁用。
- 页脚放在列表之外，所以切换分类后当前已加载条目为空时，仍然可以继续加载。
- 跨页按包名去重；服务器重复返回同一页或提前没有更多数据时，收敛总数并隐藏按钮，避免无限点击。
- 搜索仍然只取 pi.dev 返回的一页，页脚保留“当前显示前 N 项”的说明。

## 修复无 Xcode 的原生测试脚本

- `scripts/test-native.sh` 生成的临时 SwiftPM 工程缺少 MermaidKit 依赖，而 staged 源码里有 `import MermaidRender` / `import MermaidLayout`，全新目录下必然编译失败。
- 已按 `project.yml` 的固定 revision 补上 MermaidKit 和两个 product，并用全新临时目录实跑通过。

验证：

- 扩展目录测试类：39 个用例，0 失败

## Fix extension search hiding packages that exist

- Searches no longer send `type=extension` to pi.dev. pi.dev only classifies packages that declare pi entry kinds, and many installable extensions ship without that metadata, so the server filtered them out. Measured: `name=pi-pstack-v2` returns 0 with the filter and 1 without it.
- Packages without declared types are now treated as unknown rather than “not an extension”. Only packages explicitly typed `skill` / `prompt` / `theme` without extension are dropped.
- Browsing still uses pi.dev's curated extension listing.

## “No matches” no longer looks like “Unable to search pi.dev”

- Returning zero results used to throw `catalog_parse`, so every empty search claimed the site was broken.
- Empty results are now recognized from pi.dev's own empty state (`0 / N` in the count header or `packages-empty`) and rendered as “No matching extensions”. A parsing failure is only reported when the markup really cannot be read.
- An empty browse response is still treated as a failure and keeps the previous cached catalog instead of overwriting it.

## Paginated extension browsing

- Browsing no longer stops at the first 50 results. The footer shows “Loaded 50 of 3172 extensions”, and Load More appends 50 more per click with the button disabled while loading.
- The footer sits below the grid, so a category filter that matches none of the loaded items can still load more.
- Pages are de-duplicated by package name. If pi.dev repeats a page or runs out of pages early, the total is clamped and the button disappears instead of offering an endless dead end.
- Search still uses the single page pi.dev returns and keeps the “first N results” note.

## Fixed the Xcode-less native test script

- `scripts/test-native.sh` generated a temporary SwiftPM package without MermaidKit while staging sources that `import MermaidRender` / `import MermaidLayout`, so a fresh directory could never build.
- The pinned revision from `project.yml` and both products are now included, verified by running the script in a brand-new temporary directory.
