# PiWork 0.1.52

## 修复会话切换时的彩虹圈和主线程卡顿

- 修复 transcript 虚拟化过程中同一行重复写入 geometry preference 的问题。此前真实内容和高度占位会各自写一次偏好，触发 SwiftUI 的 “tried to update multiple times per frame” 布局循环。
- 每行现在只有一个稳定的几何上报器，切换真实内容/占位时不再产生重复偏好更新。
- 在会话切换期间先显示 loading mask，下一帧再提交新的会话 ID，避免同一帧内同时拆除旧 transcript 和准备新会话。
- 切换期间不再计算 transcript 投影、prompt history 和 prompt rail 偏好。
- 缓存 prompt rail 条目。此前每次 SwiftUI 布局都会重新对每个用户消息做空白归一化和截断，大会话会反复消耗主线程时间。

压力测试中，两个 200 条消息的大会话连续切换：

- 修复前：多次 400–800ms，频繁出现 preference 警告
- 修复后：大部分 26–70ms，偶发 300–500ms，preference 警告消失

## Fix session-switch hangs and beachballs

- Fixed duplicate geometry preference writes while a transcript row switches between real content and its measured placeholder. Both views wrote the same preference, triggering SwiftUI's “tried to update multiple times per frame” layout loop.
- Each row now has one stable geometry reporter shared by both states.
- Session selection is split across two frames: show the loading mask first, then commit the new session id, so a large outgoing transcript is not torn down in the same frame that prepares the next session.
- Transcript projection, prompt history, and prompt-rail preference updates are skipped while the transition mask is up.
- Prompt-rail entries are now cached. Previously every SwiftUI layout pass re-normalized whitespace and truncated every user prompt, which repeatedly consumed main-thread time on large sessions.

Stress test with two 200-message sessions switched continuously:

- Before: repeated 400–800ms switches and frequent preference warnings
- After: mostly 26–70ms, occasional 300–500ms, preference warnings gone
