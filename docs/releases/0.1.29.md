# PiWork 0.1.29

## 技能简介

- 修复上一版把大量技能误判为「没有提供简介」的问题：技能页的简介有两种发布位置，除了页面里的 Summary 段落，还有文档的 `description` 元信息。上一版只读前者，而目录里大多数页面只有后者，于是整屏卡片都显示没有简介。现在按顺序读这两处。
- 站点会给没有简介的技能页自动生成两段套话（`<技能名> — an installable skill for AI agents…` 与 `Install the … skill for your AI agent`），这些不再当作简介展示，会如实标记为没有简介。
- 同一个技能常被多个发布者重复收录，个别发布者的页面是空的（例如 `open.feishu.cn` 下的整套 Lark 技能）。这类卡片会借用同 slug 兄弟技能已经取到的简介，不再显示「没有提供简介」。
- 「没有简介」的判定改为只在页面确实答复、且内容为空时记录；超时、连接中断、限流等临时失败不再落盘成永久结论，下次进入会重新尝试。
- 旧版本写进缓存的错误判定会自动作废，升级后第一次打开就会重新取简介。

实测：目录 600 个技能中，新逻辑取到 569 个真实简介，剩余 31 个里 29 个是空页面发布者（会借用兄弟简介），真正没有简介的只有 2 个。

## Skill descriptions

- Fixed the previous build mistaking most skills for "no description published": skill pages carry the text either in a rendered Summary block or in the document's `description` meta tag, and most pages only have the latter. Both are read now, in that order.
- The site generates two flavours of filler for pages that publish nothing (`<name> — an installable skill for AI agents…` and `Install the … skill for your AI agent`). Those are no longer shown as content; the card reports a missing description instead.
- The same skill is republished under several owners, and some publishers ship empty pages (the whole Lark set under `open.feishu.cn`). Those cards now borrow the description a sibling with the same slug already resolved.
- A "no description" verdict is only recorded when the page actually answered and had nothing to say. Timeouts, dropped connections and rate limits stay retryable and are no longer persisted as permanent.
- Verdicts the previous build wrote to the cache are invalidated, so the first launch after upgrading fetches descriptions again.

Measured: across the 600 skills in the directory, the new reader resolves 569 real descriptions; of the 31 remaining, 29 sit on empty publisher pages and borrow from a sibling, leaving 2 genuinely undescribed.
