# PiWork 0.1.35

## 长会话滚动与切换稳定性

- 修复长会话向上加载历史后，向下滚动或点击“跳到最新消息”仍停在中间的问题。应用会在懒加载消息高度稳定期间重新校准到底部的位置，并且只有真正到达最新消息后才隐藏跳转按钮。
- 修复滚动边界通知在 SwiftUI 布局过程中同步修改状态的问题，避免历史加载与滚动触发布局反馈、卡顿和彩虹圈。
- 修复会话切换任务被取消后加载遮罩可能永久保留的问题；切换期间不再挂载不可见的旧消息列表，并限制骨架扫光动画的持续时间。
- 减少滚动过程中无变化的状态写入，降低长记录布局和自动跟随的重复刷新。

## macOS 发布效率与诊断

- 测试与归档现在共用锁定版本的 Swift Package 下载和二进制依赖缓存，同时仍使用独立的 DerivedData，避免复用应用编译产物。
- 新增 `main` 分支双架构依赖缓存预热，并缓存校验过的 Sparkle 发布工具；缓存未命中时仍会按锁文件正常解析依赖。
- 将 Agent Host、打包、更新、项目变更与运行时恢复检查拆分为独立步骤，便于识别耗时瓶颈。
- 保留 Xcode 测试和归档的完整日志与构建耗时摘要，即使构建失败也会上传七天供排查。

## Long-session scrolling and switching stability

- Fixes long conversations stopping short after loading older history and then scrolling down or choosing Jump to Latest. PiWork now retries tail positioning while lazy message heights settle and hides the jump button only after the real bottom is reached.
- Defers scroll-bound callbacks outside SwiftUI's active layout update, preventing history loading and scrolling from creating state/layout feedback, hangs, or a spinning beachball.
- Ensures cancelled session switches cannot leave the loading mask permanently visible. The outgoing transcript is no longer mounted behind the mask, and skeleton shimmer animation is bounded.
- Avoids unchanged scroll-state writes to reduce repeated layout work in large transcripts.

## macOS release efficiency and diagnostics

- Debug tests and Release archives now share pinned Swift package downloads and binary artifacts while retaining separate DerivedData directories and compiled products.
- Adds default-branch cache warming for both native architectures and caches verified Sparkle release tools. Cache misses still resolve normally from the committed lockfile.
- Splits Agent Host, packaging, update, project-change, and runtime-recovery checks into individually timed workflow steps.
- Uploads complete Xcode test/archive logs and build timing summaries for seven days, including failed builds.
