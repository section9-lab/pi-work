# PiWork 0.1.51

## 历史会话先显示，再连接 Agent

- 点击历史会话时，先以只读方式加载最近 40 条消息并立即显示，不再等待扩展、MCP、工具和权限状态全部初始化完成。
- 完整 Agent 运行时在后台连接；完成后自动合并模型、权限、斜杠命令和实时状态。
- 连接期间输入框上方显示“正在连接 Agent…”。此时可以直接输入并发送，消息会等连接完成后按顺序发出。
- “加载更早消息”会等后台连接完成后再请求，避免使用只读预览的临时历史位置。
- 已缓存会话仍然直接打开；旧版 Agent Host 不支持预览时会自动回退到原来的完整打开流程。
- 39MB 的超大会话也会先显示最近 40 条，不会被完整运行时阻塞。

实测：

- 典型会话只读预览：13–23 ms
- 39MB 会话只读预览：62–89 ms
- 完整 Agent 连接：约 1.1–3.5 s，仍在后台进行
- 点击到内容可见：典型会话约 100–200 ms，39MB 会话约 130–260 ms

## Show history before attaching the agent

- Opening a historical session now loads and renders the latest 40 messages in read-only mode first, without waiting for extensions, MCP, tools, and permission state to finish initializing.
- The full agent runtime attaches in the background, then merges model, permissions, slash commands, and live state.
- A “Connecting to agent…” status appears above the composer. The composer stays usable; a prompt sent during attachment is queued and sent after the live handle is ready.
- Loading earlier messages waits for attachment so it never uses the preview's temporary history cursor.
- Cached sessions still open immediately. Older hosts without preview support fall back to the original full-open path.
- Even a 39 MB session shows its latest 40 messages before the full runtime finishes.

Measured:

- Typical read-only preview: 13–23 ms
- 39 MB read-only preview: 62–89 ms
- Full agent attachment: roughly 1.1–3.5 s, now in the background
- Click to visible content: roughly 100–200 ms for typical sessions, 130–260 ms for the 39 MB session
